# 构建环境预检：先完成 Dubbo，再扩展其他受试项目

## 当前决定

在开始其余五个项目的完整构建前，先以 `D:\Java_projects\Apache\dubbo-3.3.6` 建立宿主机基线。当前不使用 Docker。

理由：Maven/Gradle Wrapper 已负责工具版本与依赖下载；现阶段已发现的问题是后台子进程没有显式继承 `JAVA_HOME`、Gradle distribution 下载超时、以及各项目的缓存没有统一配置。这些都是宿主机预检可以直接解决的问题。此时增加 Docker 会额外引入 Windows bind mount、路径长度、容器缓存、网络代理和 PIT 报告路径差异，不能更快得到论文数据。

## Dubbo 3.3.6 的已知要求

- Wrapper：`.mvn/wrapper/maven-wrapper.properties` 指定 Maven 3.9.9；必须使用 `mvnw.cmd`，不依赖机器 PATH 中存在全局 Maven。
- JDK：根 `pom.xml` 的 source/target 是 Java 8、部分编译配置为 release 8；当前 Temurin JDK 17 可以作为构建 JDK。
- 当前机器 JDK：`C:\Program Files\Eclipse Adoptium\jdk-17.0.20.101-hotspot`。
- Wrapper 对每个子进程都要求 `JAVA_HOME` 指向上述 JDK；交互式 shell 能运行 Java 不代表后台 `Start-Process` 自动继承正确变量。
- 编码：项目 `.mvn/jvm.config` 已声明 UTF-8。Windows 上仍应将 workspace 放在项目旁边，避免工具目录中的中文路径进入 Maven/JDK native path。
- Maven 缓存：为可复现的并行实验使用 `D:\Java_projects\Apache\.m2-dubbo-3.3.6`，并在 compile、test、PIT 三条命令均传 `-Dmaven.repo.local=<same path>`。

## Dubbo 基线验收

1. 在后台子进程中显式设置 `JAVA_HOME` 与 UTF-8 JVM 参数。
2. 运行 `mvnw.cmd -v`，日志确认 Maven 3.9.9 与 JDK 17。
3. 运行 `mvnw.cmd -Dmaven.repo.local=<isolated-cache> -DskipTests test-compile`。
4. 保存完整 stdout、stderr、退出码、开始/结束时间、tag/commit 和缓存路径。
5. 只有退出码为 0 时，才将该环境标为 `BUILD_BASELINE_PASSED`；存在 `target/` 文件不能替代该结论。

## 面向全部项目的预检清单

在构建任意新项目之前，先生成并保存一个 `build-manifest.json`：

```json
{
  "projectRoot": "...",
  "tag": "...",
  "buildTool": "maven|gradle",
  "wrapper": "...",
  "javaHome": "...",
  "javaVersion": "...",
  "cache": "...",
  "requiredJava": "detected or unknown",
  "testTask": "...",
  "pitCapability": "available|unavailable|unknown"
}
```

Gradle 项目额外要求：

- 使用项目自身 `gradlew.bat`，不要依赖全局 Gradle；
- 在子进程环境中显式设置 `JAVA_HOME` 和每项目独立的 `GRADLE_USER_HOME`；
- 下载 wrapper distribution 时设置合理网络超时，并将下载失败单独记录；
- 在执行 PIT 前先探测真实 Gradle task，不能默认存在 `pitest`；
- 先调用 layout probe 得到 source set、Gradle module path 与 test classpath，再开始 AST 类型解析或范围限定验证。

## 何时才使用 Docker

仅在出现以下任一情况时，为**特定项目**增加容器，而不是把所有项目一开始容器化：

- 项目要求与其他项目不兼容的 JDK，且宿主机不能并存；
- 构建依赖 Linux-only native toolchain 或系统服务；
- 在已固定 JDK、Wrapper、隔离缓存后，宿主机仍无法稳定复现 CI 构建；
- 需要发布可复现实验 artifact，且容器中已验证 PIT、测试报告和路径语义无差异。

Dockerfile 必须固定 JDK、Maven/Gradle 版本和缓存挂载策略，并把 Windows 路径、换行符和 PIT 报告挂载作为单独验收项。
