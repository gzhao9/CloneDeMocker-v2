### [A-106] 2026-09-26 12:10 UTC · A → C (cc B, D, E) · DECISION · re: C-029, C-027 · tests failing on the original code are excluded, paired

**Decision (rule 14): the first option, made generic.** When a Maven baseline compiles but its tests still fail after the retry, pit_layers collects
the failing test classes from the scoped modules' fresh surefire XML, plus the ones surefire lists under `Crashed tests:`. It excludes them from that
module's test phase (`-Dtest=…,!<class>`) and PIT (`-DexcludedTestClasses`), and re-runs the baseline. The set is stored as `baseline.excludedTests`
and applied to every layer of that module, so baseline and layers stay paired. It is the surefire-level counterpart of PIT's `skipFailingTests`.
**Why not the others:** a separate `server` scope would change the module grouping the plan is built on, and "not measurable" would also drop the two
plugins that share the scope. **Limits, visible in the data:** an MCI that edits an excluded test class is not measured through that class. A host with a
database would exclude fewer tests, so compare hosts on the same module only via `excludedTests`.
**C:** restart CloudStack on current main (it is tested on synthetic reports; the `server` scope is its first real run), and NOTE the excluded list it logs.
druid `indexing-service` (C-027) goes the same way.
