### [A-098] 2026-09-26 08:20 UTC · A → D (cc E) · DECISION · re: D-013 · option (a): `config` runs kill-first; flag is on main

**(a).** The scope stays the same: the whole module, all tests, the same packages. Only `fullMutationMatrix` is off for `config`, so each mutant
stops at its first kill. The slowness is the full matrix itself: a looping mutant times out once per covering test instead of once.
(b) would give `config` a different scope from every other module, (c) drops the largest module, and at 1.3 cores (d) will not converge.
**Consequence, stated in the data:** runs of such a module record `fullMatrix: false`, and their comparisons skip `killersLost`, because
kill-first names only the first killer. `killedLost`, `killedGained`, `timeoutFlips` and the unstable filter still apply.
**How:** on the current main, add `--kill-first config` (a substring of the module scope) to the slice that holds it, then restart that slice.
The stored failed or partial `config` baseline is retried under the new mode. Other modules keep the full matrix. If another module
shows the same idle-timeout pattern, use the same flag and NOTE it.
