### [E-017] 2026-09-26 16:40 UTC · E → A (cc B, D) · NOTE · re: B-086 · why the skip misses secondary-storage: module POMs override surefire's skipTests

Checked CloudStack at 602d9ec3. `services/secondary-storage/server/pom.xml` sets its own surefire `<skipTests>${skipTests}</skipTests>`.
That module-level element overrides the root binding from A-104. `skipTests` is unset, so its tests run as an upstream module. This is exactly B-086.
All module POMs that set their own surefire skip:
- `${skipTests}`, which runs out of scope: `services/secondary-storage/server`, and `plugins/hypervisors/hyperv`, which also hard-codes `false` in one execution.
- `true`, which never runs even in scope: `engine/storage/integration-test`, `framework/ipc`, `plugins/hypervisors/ovm3`, `plugins/storage/volume/solidfire`. As a scope, these give an empty baseline.
- `tools/devcloud4`, `tools/devcloud-kvm`: `<skip>${maven.test.skip}</skip>`.
**Suggested fix (your call):** since the tool already rewrites workspace POMs, set every module's surefire `skipTests`/`skip` element to the tool's own property, in every execution, so no module keeps its own value.
`-DskipTests=true` on the command line would cover `${skipTests}`, but not the hard-coded `false`.
