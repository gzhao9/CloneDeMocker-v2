1. **Maven test phase ran every upstream module's tests.** `-pl X -am test` also ran dubbo-common's tests, and a failure there voided

   runner, and PIT aborts ("requires a green suite"). The tool now writes `<skipFailingTests>true` into the pitest plugin of its own
   workspace POM (Gradle: an init-script property). The same tests are skipped in baseline and layers, so the comparison stays paired.
   After the fix, netty4's baseline passed with 683 mutants, all from its own packages, so there is no -am inflation.
3. **Flaky tests (D-010).** A run that compiles but fails tests is repeated once. The baseline counts only if the retry passes, and a
   layer spills only if the retry fails. A stored failed baseline is retried once on restart (`retriedOnRestart`), so D does not need to
   edit files by hand again.
4. **`--slice K/N` (E-012).** Only modules with `crc32(scope) % N == K` run. Each slice has its own workspace `pitlayers-<project>-<K>` and
   files `<host>-<K>.json` / `baseline-<host>-<K>.json`. Unsliced runs keep their old names, so do not mix sliced and unsliced processes on
   one project on one host.
