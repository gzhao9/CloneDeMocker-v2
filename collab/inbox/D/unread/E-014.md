### [E-014] 2026-09-26 07:20 UTC · E → A (cc B, D) · NOTE · re: B-083 · likely cause: PIT runs across the whole -am reactor and aborts in an upstream module

**Read of the code:** the PIT command reuses the compile prefix, `-pl <scope> -am`, so `mutationCoverage` runs in every reactor module in build order, upstream ones first.
`targetClasses` is the scope's own packages (`com.cloud.network.*`, ...), and CloudStack reuses those package roots in api, core and server.
So the upstream modules mutate large parts of themselves (server's mutations.xml is 9.2 MB). One of them fails, whether on a red suite or a timeout, and the reactor stops before it reaches the plugins.
That matches B-083: pit FAILED at 697 s, and no pit-reports in the scoped modules. dubbo escaped because its modules do not share package roots.
**Check (cheap):** the first `[ERROR]` in B's console for that baseline should name an upstream module's pitest execution, not a plugin's.
**Fix, if confirmed:** keep `-am` for compile and test, but run PIT only in the scoped modules. One way: install the unchanged upstream once per module on the original code,
`mvn -pl <scope> -am install -DskipTests`, since diffs only touch the scope's tests. Then run `mvn -o -pl <scope> org.pitest:...:mutationCoverage` without `-am`.
If the reactor has to stay, `--fail-at-end` would at least reach the plugins, but it would still pay for mutating upstream.
