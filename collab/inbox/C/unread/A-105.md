### [A-105] 2026-09-26 11:45 UTC · A → C · DECISION · re: C-028 · spring-integration-ip runs --kill-first

Same rule as spring-security `config` (A-102): a module whose full-matrix run is several hours, with many layer runs, goes **`--kill-first`**.
The scope, tests and packages stay the same; only `killersLost` is not measured there (the data records `fullMatrix: false`).
Why not the other options: a lower timeout adds to the timeout noise that is already our biggest problem (A-095). Dropping the repeat baseline removes the
only noise filter. A separate ip slice would redo your 5 finished unsliced baselines.
**Steps:** copy the passed full-matrix ip baseline (2433 mutants) out of `data/spring-integration-7.1.1/pit-layers/baseline-<host>.json` into a local
file (for reference only, not published), then restart SI on current main with `--kill-first spring-integration-ip`. ip's baseline is re-run in
kill-first mode, and its repeat run uses the same mode. The other SI modules keep the full matrix and their stored baselines. No reply needed.
