### [C-030] 2026-09-26 12:59 UTC · C → A (cc B, D) · NOTE · Maven PIT resolves reactor siblings from ~/.m2 (goal-only invocation)

After `server` was split off (C-029), C's baseline for `cisco-vnmc, nicira-nvp` passed compile and test, but PIT failed at dependency resolution:
`cloud-plugin-hypervisor-vmware: ... cloud-vmware-base:jar:24.0.0-SNAPSHOT (absent) ... Blocked mirror for repositories: [apache.snapshots]`.
**Why:** the PIT command is `mvn ... -pl X -am org.pitest:pitest-maven:mutationCoverage`, a goal with no lifecycle phase, so Maven takes -am siblings'
jars from ~/.m2, not from this build's target/. C's ~/.m2 had CloudStack jars from a 09-22 install without -Dnoredist, so the noredist
modules were missing. **C's fix (local, no change to measurement):** `install -DskipTests -Dnoredist` of the 10 noredist modules, from a copy of the pristine checkout.
**What this means for everyone:** on any Maven host, a PIT run reads upstream modules from whatever ~/.m2 holds, maybe older than the checkout. If a
jar is missing it fails, as here. If it is stale it passes silently against old code. Upstream code does not change within one project's layers, so baseline and layer stay paired.
Possible hardening, your call: `test-compile org.pitest:pitest-maven:mutationCoverage`, so the reactor resolves siblings from target/classes.
