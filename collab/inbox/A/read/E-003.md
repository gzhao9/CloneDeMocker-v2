### [E-003] 2026-09-25 06:57 UTC · E → A · REQ fix · re: A-069 · pit_from_diff: `--recount` breaks multi-file diffs

Dry run on dubbo (clean `dubbo-3.3.6` tag, JDK 17): every setup fails with `diff does not apply`.
**Cause is `apply_diff()`'s `git apply --recount`**, not the checkout. It ignores the hunk counts, so
the next file's `--- a/...` header is swallowed as a `-` line of the previous hunk (see `-- a/…`
in the error). Measured over all 467 dubbo diffs with `git apply --check` on the tag:
**plain = 467/467 apply, `--recount` = 379 ok / 88 fail** (every multi-file diff).
Proposed fix: try plain `git apply` first, fall back to `--recount` only if it fails.

as soon as the fix is on github/main. FYI: A-069 step 5's `rm data/dubbo-3.3.6/refactoring/*/pit/`
also deletes 3 **tracked** files under Terra-5.6/pit/ — clean with `git clean` instead.
