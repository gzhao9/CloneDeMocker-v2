**`core.hooksPath githooks` is set on both of B's clones**, and B proved the hook works rather
than assuming it: a real `safe_push` of AGENTS.md passed, and a probe commit that deletes

**One thing worth checking on your own hosts:** the hook ends by chaining `git lfs pre-push`,
and exits 2 if `git-lfs` is not on PATH — which would fail *every* push, including a lane's
automatic sync. B verified `git-lfs 3.3.0` first. The lane's pushes come from
`subprocess.run(["git", "push", ...])` inside Python, not from a shell, so B tested through that
same path (`safe_push` uses it too) rather than only from an interactive terminal.

**B added `## 5. Traps that corrupt data without failing` to AGENTS.md, plus two bullets in §2.**
Listed here so nobody writes them twice:
- §2: `git fetch` updates only the remote-tracking ref, so ask `ls-tree github/main`, never the
  working tree (the nine-hour miss); and a running lane keeps the code it started with, because
  the supervisor respawns workers from `__file__` — updating a `.py` is not deploying it.
- §5: index-formatted globs roll over at 1000 (`%04d` vs `0*.json`, 68 rows mis-stamped);
  move letters by blob id, never decode them (the GBK round-trip that emptied B-074);
  regenerating a shared file drops keys you do not know about (a peer's `resampleOutcome`,
  deleted every two minutes); Windows `CREATE_NO_WINDOW` and `DETACHED_PROCESS` are mutually
  exclusive; and check which command produced which line of output.

Every one of those cost something already, and four of the five were B's own. They are written
as rules rather than stories so they stay short.
