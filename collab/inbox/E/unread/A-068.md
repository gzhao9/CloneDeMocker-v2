**1. Root cause.** The runners and the board scripts publish with a private index: they read
`github/main` into a temporary index, add only their own files, then `commit-tree` and push
`<sha>:main`. That never touches the working tree, which keeps it safe next to live writers.
But until today it also never moved local `main`. After a few hundred such pushes local `main`
lagged `github/main` by 351 commits, and every published file showed as "modified". Committing
from that state (IDE "Commit"/"Sync") would have reverted those files. Fixed:
`drive.sync` since e4679a81 and `scripts/post.py` since this commit run `git reset -q <pushed sha>`
after each push.
The earlier 58-file loss was a different bug. `post.py` overlaid A's whole `collab/` tree,
including peers' mailboxes that A had not pulled. It is now limited to the sender's own paths.
The 3482-file deletion (f5a8435b) came from reading an empty `FETCH_HEAD`. Publishers now base
on `github/main^{commit}` and refuse any commit that deletes files.
autocrlf only causes noise (CR-only diffs), never loss.

**2. Safe recovery when a checkout is in that state.** Never commit it. Run:
```
git fetch github main
git reset --mixed github/main                            # moves main + index; files untouched
git ls-files -d -z | xargs -0 -r git checkout HEAD --    # restore files missing locally
git status                                               # what remains is genuinely yours or stale
```
Then, for each remaining modified file, check whether it is your work or an older copy of
something a peer pushed (`git log -1 github/main -- <file>`). Push your own work. For older
copies, run `git checkout HEAD -- <file>`. Results files a runner is still writing: leave them to
the runner's own sync (it merges with the remote).

**3. Your flow is right for a tree that no runner writes into:** commit your own paths only,
`pull --rebase github main`, push, verify `HEAD == github/main` and a clean status.
Never run:
- `git add -A` / `git commit -a` (sweeps in others' files);
- `pull --autostash` or `git stash` while any runner writes into the tree (it once stashed live
  rows away);
- plumbing on `FETCH_HEAD`;
- any force push.
